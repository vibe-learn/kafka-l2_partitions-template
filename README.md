        # kafka — Партиции и параллелизм

        Homework-шаблон для урока **l2_partitions** (Партиции и параллелизм) на платформе Vibe Learn.

        ## Что делать

        Напиши Go-программу, которая запускает локальный Kafka через Docker Compose, создаёт топик
с 3 партициями, затем отправляет 100 сообщений с ключами user_0 … user_4 (key = "user_" + strconv.Itoa(i % 5)).
Консьюмер собирает для каждого ключа множество партиций, в которых были получены его сообщения.
CI-проверки: (1) все сообщения с одинаковым ключом получены из одной и той же партиции;
(2) 5 уникальных ключей распределились максимум по 3 партициям (≤ partition_count).

## Контекст (из transfer-задачи урока)

Команда вашего продукта решила добавить аналитику в реальном времени поверх существующего
топика `user_events`. Текущая топология: 6 партиций, key = `user_id`. Аналитики просят,
чтобы события одного пользователя приходили в одну партицию — иначе оконные функции врут,
потому что они видят только часть событий пользователя.

Через 3 месяца DevOps хочет «добавить ещё 6 партиций для роста» — перейти с 6 на 12
партиций, чтобы поддержать возросший throughput.

## Recap из урока

- Партиция — это **единица параллелизма**: максимальный параллелизм чтения в группе равен числу партиций.
- Ключ сообщения детерминирует партицию: `partition = murmur2(key) % N`. Один ключ → одна партиция → локальный порядок для этого ключа.
- Порядок гарантирован только **внутри одной партиции**. Между партициями глобального порядка нет.
- Увеличение `partition_count` — **однонаправленный рычаг**: это breaking change для per-key порядка. Планируйте число партиций заранее с запасом.
- Изменить partition key безопасно можно только через **re-keying**: создать новый топик и переписать события через stream-processing (Kafka Streams / Flink).

        ## Как работать

        1. Платформа Vibe Learn создаёт копию этого репо в твоём GitHub-аккаунте по клику «Начать домашку» на странице урока (через GitHub `/generate`, codecrafters-pattern).
        2. Склонируй копию локально, реализуй TODO в `main.go`, прогони тесты, запушь.
        3. CI (`.github/workflows/ci.yml`) запускает `go vet` + `go test ./...` на каждый push. Платформа слушает результат через webhook от GitHub Actions и обновляет статус домашки на странице урока.

        ## Локальное окружение

        - Go 1.22+
        - Docker + docker-compose — `docker compose -f docker-compose.yml up -d` поднимает 3-нодовый Kafka cluster на портах 9092/9093/9094, использовать в тестах через bootstrap `localhost:9092,localhost:9093,localhost:9094`.

        ## Запуск

        ```bash
        # Поднять локальный Kafka
        docker compose up -d

        # Прогнать тесты (часть из них стартует свой ephemeral testcontainers cluster, часть использует docker-compose выше)
        go test ./...

        # Запустить main (печатает marker; замени stub на реализацию)
        go run .
        ```
